# 水下考古潜水记录

直接打开 `index.html` 使用（三个业务文件需与页面同目录）：

- `rules.js` — 判断（业务规则）：保存/移除进草稿、冲突保留、封存校验与封存、页面取数
- `archive.js` — 存档：localStorage 读写，标记、草稿、封存快照、修订履历的持久化
- `page.js` — 页面操作：地图、表单、筛选、草稿确认面板、封存入口与导出

## 换班协作规则

1. **保存和移除先进入确认草稿**：每条标记（按编号）至多保留一份未确认改动，经“确认生效”后才真正写入；可随时“丢弃”。
2. **冲突不覆盖**：草稿期间同一编号又被别的班次改动，后提交的人会看到“冲突项”并保留其新值，但不会覆盖前一份；由确认人“采纳新值”或“忽略”后才能确认。
3. **潜次封存**：封存前必须清空涉及该潜次的全部草稿（保存草稿的新潜次、原标记潜次都会计入）。封存后仍允许保存/移除，但只进入“修订履历”，页面显示与 JSON 导出沿用封存版快照。
4. 原有类型筛选、潜次时间线与 JSON 导出照常可用；导出始终导出当前可见版本（已封存潜次为封存快照）。
